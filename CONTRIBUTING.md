# Contributing to Data Artisan

Thanks for interest in contributing! Here's how to help.

## Ways to Contribute

### 1. Report Issues
Found a problem with a skill? Open an issue with:
- Which skill (e.g., data-schema-design)
- What you tried
- What went wrong
- What you expected

### 2. Suggest New Skills
Have an idea for a skill that's missing? Start a discussion:
- What problem does it solve?
- Why is it important for data engineers?
- Any real-world examples?

### 3. Improve Existing Skills
See a gap in an existing skill? You can:
- Suggest new patterns to add
- Improve examples
- Fix unclear instructions
- Add edge cases

### 4. Write Examples
Help other developers by:
- Contributing real-world schema examples
- Sharing ETL implementations
- Writing data quality checks you've used

## Before You Submit

1. **Test your changes** – If you modify a SKILL.md, try it in Claude Code or Cursor
2. **Follow the structure** – Copy the format of existing skills
3. **Be clear** – Assume the reader is learning; explain reasoning
4. **No marketing** – Skills should teach patterns, not promote tools (unless neutral comparison)

## Pull Request Process

1. Fork the repo
2. Create a branch: `git checkout -b add-your-skill`
3. Make changes
4. Test in Claude Code / Cursor
5. Commit with clear message: `Add Kafka streaming patterns skill`
6. Push and open a PR

## Code of Conduct

- Be respectful
- Welcome all skill suggestions
- Assume good intent
- Focus on patterns, not personal opinions
